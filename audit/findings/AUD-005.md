# AUD-005: Consent can deliver a different application's keys than the signed OAuth client

- Type: Defect (composition)
- State: Fixed 2026-09-20; verified locally ([evidence](../evidence/2026-09-20-remediation-wave1.md)); platform e2e verified 121/121 (2026-09-20)
- Severity / rationale: Critical — disclosure of a target app's scoped encryption and signing keys via unsigned URL-parameter trust
- Confidence and evidence basis: source-confirmed, cross-verified
- Owner: remediation wave 1
- Affected repositories, revisions, and local patches: `betterbase-accounts` fix `6cd6f62` (oauth.rs, lib.rs, consent/login/signup/recovery-setup.tsx, api.ts)
- Violated invariant / linked decision: INV-04; D-004

## Impact and preconditions

A registered malicious client could get the user's browser to wrap a *target* app's keys to the attacker's recipient by tampering the duplicated unsigned consent URL params. See review 01 A-03.

## Remediation (implemented)

Server: authorize redirect carries only the signed state; new auth-gated `GET /oauth/consent-context` returns client/scope/redirect/recipient from the signed state + client table; `POST /oauth/consent` requires the `keys_jwe`+`keys_jwk_thumbprint` pair when delivered, validates the thumbprint against the RFC 7638 thumbprint of the *signed* `keys_jwk` (constant-time), rejects delivery without a signed recipient, and requires delivery for the sync flow (no silent downgrade). SPA: consent page fetches the server-validated context and uses it for display, grant lookup, and the JWE recipient; login/signup/recovery-setup round-trip only the `oauth` param. A known-answer vector pins the shared RFC 7638 construction (server/SPA/SDK).

## Verification

Route tests: thumbprint mismatch / partial pair / no signed recipient / sync silent-downgrade all rejected; matching thumbprint creates a code; context endpoint returns signed fields, rejects invalid state, requires auth. Platform e2e consent journeys are the integration gate (pending). Verifier: remediation agent, 2026-09-20.

Remaining follow-ups (defense in depth, not required for this fix): SDK `key_extraction.rs` should enforce the configured client ID in the extracted payload; component-level SPA tamper tests once component-testing infra exists.
