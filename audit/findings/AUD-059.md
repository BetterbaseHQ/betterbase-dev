# AUD-059 — RustSec rsa advisory + npm advisories across workspaces (F-05)

**Severity:** Medium · **Status:** Fixed with two accepted residuals (wave 10; accounts `fb3c5f1`, sync `a657e6b`, inference `8190318`, SDK `eecda45`, examples `4bb0bac`).

## Finding
`rsa 0.9.10` (RUSTSEC-2023-0071, "Marvin Attack" timing, CVSS 5.9) in all three Rust server lockfiles via `jsonwebtoken`; 47 npm advisory matches across 11 web workspaces (13 in accounts web incl. 6 high runtime-class react-router; 7 in notes; build-tool chains elsewhere).

## Fix
**RustSec — accepted with rationale, made visible-gated**: no fixed rsa release exists upstream. Every JWT operation in accounts/sync/inference pins ES256; no RSA key is ever loaded, so there is no private-key timing oracle. Each repo now carries `.cargo/audit.toml` ignoring exactly this advisory with that rationale in-file; `cargo audit` exits 0 in all three (verified) so *new* advisories fail loudly instead of drowning in a known-accepted one.

**npm — 47 → 2 accepted**:
- accounts web: react-router re-resolved within range to fixed releases (13 advisories cleared, 6 high).
- uuid (all workspaces, dev-only transitive): forced `^11.1.1` via `pnpm-workspace.yaml` `overrides:` — pnpm 12 no longer reads `pnpm.overrides` from package.json (discovered empirically; the dead package.json entries were removed).
- rollup/esbuild: the sweep dropped vite 8's *optional* build peers, breaking browser-test config load (`vite-plugin-top-level-await` requires rollup at import time) — fixed by making both explicit devDeps, esbuild at the advisory-patched `^0.28.1` (SDK + 7 apps).
- linkify-it/markdown-it (notes, runtime-class): re-resolved to fixed releases.

## Accepted residuals (documented, not fixed)
- **notes `@tiptap/core` 2.27.2** (GHSA-cp6q-959q-f8rh, moderate, runtime-class): the patch is tiptap **3.30.4** — a 2→3 major editor migration, out of scope for a dependency-hygiene wave. Reachability not established: the advisory requires untrusted-attribute handling; notes uses standard fixed schemas that discard unknown attributes.
- **shared `esbuild` 0.27.7** (low, build-only): pinned by tsup's own dependency range cap (`pnpm update` cannot cross it without an override that would fight tsup's expectations); esbuild in the SDK/apps is at the patched release.

`cargo audit` ×3 exit 0; `pnpm audit`: 9 of 11 workspaces clean, shared 1 low, notes 1 moderate (the residuals above). Full platform validation: `just check-all` exit 0 (incl. SDK 519+200 browser suite on the repaired peer graph), `just e2e` 125+3, faults 3/3. Fresh scan numbers recorded in `audit/evidence/dependencies.md` (wave-10 section).
