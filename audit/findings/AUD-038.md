# AUD-038 — Trusted peers can rebroadcast into unrelated spaces (C-15)

**Severity:** High (trust-boundary integrity) · **Status:** Fixed (wave 7, commit betterbase-sync `0bb94a7`).

## Root cause
The federation notification dispatch called `handle_federation_rebroadcast`, which broadcast the supplied space/payload to local subscribers without checking a UCAN, a current subscription, or peer authority for that space — a compromised trusted peer could inject unsolicited notifications/control metadata (tombstones, key_generation, revocation reasons are not ciphertext-authenticated) into any space it could name.

## Fix
Rebroadcasts are gated on the sending connection's own validated subscription: `RealtimeSession::is_subscribed(space)` must hold for the frame's target space before any fan-out. Subscriptions are granted only by the federation subscribe RPC after UCAN (or FST) validation, so the gate transitively enforces the same per-space authorization the explicit pull/push paths apply. Drops are logged with peer + space for operator visibility.

## Tests
`websocket_federation_rebroadcast_requires_subscription` (end-to-end over real WebSockets): a federation peer subscribed to space A rebroadcasts into the client's personal space → nothing is delivered; the same frame for space A → delivered. Verified failing on the parent commit (pre-fix code fanned out both).
