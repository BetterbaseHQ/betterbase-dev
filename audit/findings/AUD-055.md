# AUD-055 — Production recipe serves plain HTTP; TLS env unwired (F-01)

**Severity:** High · **Status:** Fixed (wave 10, dev-repo commit, post-`d2b519c`).

## Finding
The Caddyfile *supported* env-driven TLS (`{$ACCOUNTS_SITE::5377}`, ACME email) but the production compose recipe never wired it: the caddy service had no `environment:` block, published only 5377/5379 (no 80/443), and mounted no certificate-storage volume. Every production deployment therefore served plain HTTP regardless of `.env`, and a custom Caddy override would have had no cert persistence across restarts.

## Fix (`docker-compose.yml`, caddy service)
- **Env wired** with explicit defaults that preserve local behavior exactly: `ACCOUNTS_SITE=${ACCOUNTS_SITE:-:5377}`, `SYNC_SITE=${SYNC_SITE:-:5379}`, `ACME_EMAIL=${ACME_EMAIL:-admin@localhost}` (empty-string env vars would break Caddy site-address parsing, so defaults are explicit).
- **Ports 80/443 published** alongside 5377/5379 — hostname mode (HTTPS+redirect on 80/443) and localhost mode (HTTP on 5377/5379) each leave the other's ports dark inside the container.
- **Cert persistence**: `caddy_data:/data` + `caddy_config:/config` volumes (without them every restart re-issues certificates and burns ACME rate limits).
- Deployment surface documented: `.env` template in `scripts/setup.sh` (commented `ACCOUNTS_SITE`/`SYNC_SITE`/`ACME_EMAIL`/`SYNC_ENDPOINT`/`SMTP_*`) and root `AGENTS.md` ("Production deployment" section: TLS toggle, `OAUTH_ISSUER` must match the accounts hostname in TLS mode).

## Verification
- `docker compose -f docker-compose.yml config -q` and merged `-f docker-compose.yml -f docker-compose.dev.yml config -q` both parse.
- `caddy validate` inside the actual plugin-built image (`./caddy` Dockerfile, caddy-ratelimit) — **both modes**: defaults (localhost HTTP) and `ACCOUNTS_SITE=accounts.example.com SYNC_SITE=sync.example.com ACME_EMAIL=ops@example.com` (auto-HTTPS). Both "Valid configuration".
- Dev stack unaffected: dev override disables caddy via the `production` profile; e2e runs its own compose.

## Documented residual
Real ACME issuance against a public hostname was not exercised (no public DNS/ports from this machine) — the fix is config-verified in both modes, not issuance-tested. Rate limits on Let's Encrypt's side apply to first boot on a real domain.
