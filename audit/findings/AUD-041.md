# AUD-041 — E2EE claim vs plaintext quick-start (D-01)

**Severity:** High (claim/integration) · **Status:** Fixed (wave 8, commit betterbase-inference `0316732`) — claim corrected + enforcement path; reference client deferred.

## Finding
The README guaranteed "the proxy authenticates and rate-limits but never sees plaintext inference content," while the documented quick-start sent an ordinary plaintext JSON body and nothing in the repo (proxy, SDK, examples) implemented client-side encryption or attestation verification. The proxy forwards `Ehbp-Encapsulated-Key`/`Ehbp-Response-Nonce` when a client sends them, but no client did.

## Why the fix is claim-first, not client-first
In Tinfoil's architecture encryption and attestation verification live in the client. The EHBP wire protocol has no in-repo specification, and implementing an encryption protocol by inference from two header names would be guessing at cryptography — worse than an honest posture. The defect being remediated is the *mismatch* between the claim and reality; that is fixed by making the documentation true and giving operators a way to enforce the intended posture.

## Fix
- README rewritten: the unconditional "never sees plaintext" guarantee is replaced with a prominent confidentiality note stating encryption is the client's job, the quick-start sends plaintext the proxy can read, and no reference EHBP client exists yet (v1.x work item).
- New `REQUIRE_EHBP` config (default `false`): when enabled, `/v1/chat/completions` rejects any request lacking `Ehbp-Encapsulated-Key` with 400 — no plaintext prompt can transit the proxy, at the cost of requiring EHBP-capable clients. `/.well-known/hpke-keys` (bootstrap) and `/v1/models` (no user content) are exempt. The gate checks header *presence*, not cryptographic validity — a hostile client sending a junk header endangers only its own prompt (documented in config).
- Regression test: `test_require_ehbp_rejects_plaintext_chat` (400 without the header; request proceeds with it).

## Residual (documented)
No checked-in reference client implements EHBP encryption/attestation verification; until one lands, `REQUIRE_EHBP` protects only deployments whose clients implement Tinfoil's client-side encryption themselves. Tracked as a v1.x work item.
