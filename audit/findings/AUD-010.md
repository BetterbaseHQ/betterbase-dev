# AUD-010: An in-flight refresh recreates a logged-out session

- Type: Defect (race)
- State: Fixed 2026-09-21; verified locally ([evidence](../evidence/2026-09-21-remediation-wave4.md))
- Severity / rationale: High — logout does not reliably terminate local authentication; late response can overwrite a replacement session during account switching
- Confidence and evidence basis: reproduced against the real AuthSession control flow (Node harness, 8/8 assertions, 2026-09-20 identity verification wave)
- Owner: remediation wave 4
- Affected repositories, revisions, and local patches: `betterbase` fix `de859ed` (js/src/auth/session.ts)
- Violated invariant / linked decision: INV-08; D-004

## Impact and preconditions

`destroy()` marks the session disposed, but a refresh already awaiting the token endpoint then applied the response and re-persisted credentials without checking disposal — a successful restore after logout was observed.

## Remediation (implemented)

`doRefresh` captures a session generation (bumped on every cleanup — destroy/dispose/cross-tab logout), checks it after every await and at entry, and aborts before applying a response that arrived after disposal; `persist()` refuses state writes after disposal.

## Verification

Vitest: pending refresh resolving after `destroy()` rejects, does not re-persist credentials, `getToken()` stays null; a disposed session's late response does not overwrite a replacement session's persisted state; the retry-backoff loop aborts after destroy instead of cycling. Verifier: remediation agent, 2026-09-21.
