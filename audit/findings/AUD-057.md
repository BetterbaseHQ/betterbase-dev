# AUD-057 — Caddy rate-limit tiers target obsolete HTTP sync routes (F-03)

**Severity:** Medium · **Status:** Fixed (wave 10, dev-repo Caddyfile changes).

## Finding
Three dedicated sync tiers (`sync_events`/`sync_push`/`sync_pull`) rate-limited `/api/v1/events`, `/api/v1/spaces/{id}/push`, `/api/v1/pull` — routes that **no longer exist in the sync router at all** (client sync is exclusively WebSocket RPC on `/api/v1/ws`). The actual WS upgrade request fell through to the generic 600/min default with no long-lived-connection proxy settings; dead config implied protection that wasn't there.

## Fix (`caddy/Caddyfile`, sync site)
- **Removed** the three dead tiers.
- **Added `sync_ws`** (`/api/v1/ws`, 120 connection upgrades/min per IP) with long-lived transport settings (`flush_interval -1`, `read_timeout 24h`) — previously only the dead events tier carried these.
- **Added `sync_federation_ws`** (`/api/v1/federation/ws`, 60/min) with the same transport settings.
- **Added `sync_federation_http`** (trusted-keys listing + per-domain status, 300/min).
- **JWKS** (`/.well-known/jwks.json`) joined the health tier (300/min) — fetched by accounts and federation peers.
- File upload/read tiers kept (routes exist when file storage is enabled).
- Header documentation rewritten to state the honest model: **HTTP tiers rate-limit connection upgrades; per-message/per-connection abuse on established sockets is bounded server-side** (broker `max_connections_per_mailbox`, default 3; `FederationQuotaTracker` per-peer connection quotas).

## Verification
`caddy validate` with the real plugin-built image in both localhost and hostname modes: Valid. Tier structure cross-checked against the sync router's registered routes (`betterbase-sync/crates/api/src/lib.rs`): every named path exists; no dead path remains.

## Documented residual
e2e deliberately runs without Caddy (rate limiting not under e2e test — unchanged posture, stated in `e2e/compose.yaml`); tier numbers are design/config-review values, not load-tested thresholds.
