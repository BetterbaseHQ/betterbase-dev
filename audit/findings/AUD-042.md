# AUD-042 — Empty issuer/audience restrictions permitted (D-02)

**Severity:** Medium (defaults) · **Status:** Fixed (wave 8, commit betterbase-inference `0316732`).

## Finding
`ISSUER` and `AUDIENCES` were optional with no defaults; unset values produced a validator that accepted ES256 tokens from any issuer/audience the JWKS authority signs for — a token-confusion hazard whenever that authority issues inference-scoped tokens for other services. The README production example configured neither; startup only logged a warning.

## Fix
Fail closed: `config::validate_auth_binding` requires a non-empty issuer and at least one audience outside dev mode; `main.rs` exits at startup with an error naming the missing variable. Dev mode (which already defaults both) is exempt. README production example and config table updated — both variables are documented as required.

## Tests
`test_auth_binding_fails_closed_without_issuer`, `test_auth_binding_fails_closed_without_audiences` (error names the variable), `test_auth_binding_accepts_full_configuration`, `test_auth_binding_dev_mode_exempt`.
