# AUD-046: Peer update during the notes debounce window replaces the pending save; unsynced keystrokes never reach the database

- Type: Defect
- State: Fixed 2026-09-21; verified locally (notes `pnpm check` green incl. new regression; shared + SDK checks green)
- Owner: remediation wave 3
- Affected repositories: `betterbase-examples/notes`, `betterbase-examples/shared`, `betterbase` (TypedAdapter `getWithBase` passthrough)
- Violated invariant: INV-03/INV-08 (draft reaches the database)

## Remediation (implemented)

Flush-before-rebase in `NoteEditor`:

- The external-sync effects (title input and editor body) now **flush the
  pending debounced save before rebasing to the peer content**. The flush
  writes the draft anchored to the base captured at keystroke time, so it
  CRDT-merges with the incoming peer version instead of being discarded
  when the next keystroke replaces the debounce args.
- Mantine's `useDebouncedCallback` was replaced with a new
  `useFlushableDebouncedCallback` (examples-shared) because Mantine's
  `flush()` does not cancel the pending `setTimeout` — only zeroes the
  timer ref. After a forced flush, a stale timeout re-fires the *old*
  arguments once another call re-arms the ref, silently swallowing the
  newest save (observed directly while testing: the post-rebase keystroke's
  save never landed). The replacement cancels the timer and fires the
  pending args exactly once.
- Note-switch flush and unmount flush behavior preserved.

## Verification (regression tests)

- `notes/src/App.test.tsx` "peer title update mid-debounce doesn't discard
  the pending draft": types a draft, delivers a peer title update inside
  the debounce window, types again on the rebased input; asserts the draft
  write actually fired (patch spy) and the draft lineage wins the LWW race
  (`title: t.string()` is LWW — the fix's guarantee is that the draft is
  *written through*; RGA fields like `body: t.text()` additionally merge
  both writers, covered by SDK base-merge tests).

## Residuals / judgement calls

- `title` is `t.string()` (LWW by schema design): concurrent title edits
  resolve last-writer-wins rather than character merge. Changing the field
  type is an app-schema decision, not part of this fix.
- Rich-text body merge quality (JSON structure of TipTap docs under
  character-level merge) remains the known representation limitation
  recorded in the original review — unchanged.
