# AUD-016: Recovery setup replaces the previous recovery secret before confirmation

- Type: Defect
- State: Fixed 2026-09-21; verified locally ([evidence](../evidence/2026-09-21-remediation-wave4.md))
- Severity / rationale: High — closing/refreshing the page invalidated the previously recorded phrase with the new one unrecorded
- Confidence and evidence basis: source-confirmed, qualified (in-flight window)
- Owner: remediation wave 4
- Affected repositories, revisions, and local patches: `betterbase-accounts` fix `d7a9671` (web recovery-setup page, mnemonic display)
- Violated invariant / linked decision: INV-05; D-004

## Impact and preconditions

The page generated a mnemonic on mount and immediately stored the encrypted root; the continue action did not check whether storage had succeeded.

## Remediation (implemented)

The blob is stored only when the user acknowledges saving the phrase (continue): derive, encrypt, store, and only then navigate. A failed store shows an inline error with the card kept for retry; the previous recovery path stays intact until the write lands. MnemonicDisplay gained a `disabled` prop for the in-flight window.

## Verification

Component tests (happy-dom): no store on mount; store + navigate only after acknowledgment; failed store stays on the page with an error and a successful retry navigates. Verifier: remediation agent, 2026-09-21.
