# AUD-037 — Outgoing federation connections discard realtime notifications (C-14)

**Severity:** Medium (synchronization/availability) · **Status:** Fixed (wave 7, commit betterbase-sync `0bb94a7`).

## Root cause
`PeerConnection` read its socket only while awaiting one RPC response; the wire decoder classified every notification frame as `Other` and the read loop discarded it. Home-server realtime changes sent back on a subscribed outgoing socket never reached the local broker. (Related: no response deadline existed — a stalled trusted peer held the per-peer mutex forever.)

## Fix
- Per-socket dedicated reader task (split sink/stream): responses and chunks route to pending calls via per-request `Notify` slots; notification frames decode into method + params.
- Notifications are gated to spaces this manager subscribed to on the peer (outgoing counterpart of the AUD-038 gate) and delivered to a `PeerNotificationHandler` sink; the app runtime wires the sink to the local `MultiBroker`, so proxied clients receive home-server updates in realtime.
- 60-second response deadline (chunks included) converts a stalled peer into a connection reset with reconnect on next call.
- `subscribe()` pre-registers requested spaces so notifications that race subscribe-completion pass the gate (empty tokens mirror the existing decode-failure fallback), and logs `SubscribeResult.errors` instead of silently reporting success.

## Tests
- `federation_peer_manager_delivers_notifications_during_call`: peer pushes a notification *before* answering subscribe; the notification reaches the handler and the call completes.
- `federation_peer_manager_drops_notifications_for_unsubscribed_spaces`: pushed frames for never-subscribed spaces do not reach the handler.
- All 8 pre-existing federation_client behavior tests pass unchanged against the restructured reader (FST storage, chunk collection, close-retry, restore-subscriptions).
