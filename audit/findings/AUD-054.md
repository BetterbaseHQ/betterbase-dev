# AUD-054 — Partial column-deletion failure hides surviving cards (E-10)

**Severity:** Medium · **Status:** Fixed (wave 9, commit examples `1750bd5`).

## Finding
The local board's `deleteColumn` fired child card deletes individually (from render state, which can omit a just-committed card) with per-child catches, then deleted the column unconditionally — a failed card delete left the card orphaned under a deleted column, unrendered and unreachable in the UI.

## Fix
Local `deleteColumn` delegates to the SDK's `deleteTree(db, columns, columnId)`: children are discovered from the **db** via declared parent edges (not render state), deleted deepest-first, and the parent column is deleted only when they are all gone — on partial failure `DeleteTreeError` leaves the column intact so surviving cards stay visible and a retry converges. (The authenticated path already used `deleteTree`; its fail-fast semantics — deepest-first, parent last, break on failure — are pinned by the SDK's own `delete-tree` tests.)

## Tests
`AUD-054: deleting a column cascades its cards through the gated tree` — a happy-path regression net (green on parent; it pins the cascade end state and the db-discovery of a just-committed card, not the failure mode). **The partial-failure gating semantics are carried by the SDK's `delete-tree` tests** — this record does not claim the app test pins them.
