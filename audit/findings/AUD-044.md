# AUD-044 — No aggregate bounds on public/streaming proxy routes (D-04)

**Severity:** Medium (assurance gap) · **Status:** Fixed (wave 8, commits betterbase-inference `0316732` + `f1ac02c` review round) — corrected after independent review.

## Finding
Proxied request bodies streamed with no size cap; the 60s timeout covered only response headers, leaving SSE streams unbounded in idle time and total duration; no global limiter bounded the public `/.well-known/hpke-keys` route, whose upstream fetch carries the Tinfoil API key. The per-user token bucket counts request starts only, so accumulated slow streams were unbounded by construction.

## Fix (as corrected by review)
- **Request bodies**: 10MiB default cap (`MAX_REQUEST_BODY_BYTES`) enforced two ways — declared oversize via `Content-Length` fails fast with 413 (`check_request_size`), and the body is wrapped in `http_body_util::Limited` so chunked or lying bodies error the stream once the cap is exceeded, tearing down the upstream request. *(Review correction: axum's `DefaultBodyLimit` layer was originally claimed as the streaming backstop — it is provably inert for a streaming proxy (extractor-applied only; verified against axum-core source), and was replaced with the explicit `Limited` wrapper.)*
- **Response streams**: `bounded_upstream_stream` enforces a 120s inter-chunk idle deadline and a 15min absolute budget; a stalled stream terminates with a `TimedOut` error and downstream cancellation drops the upstream response.
- **Concurrency**: a global semaphore (`MAX_UPSTREAM_CONCURRENCY`, default 256) bounds concurrent upstream **connections across *all* proxy paths — including public `hpke_keys`**. The permit is acquired before proxying and moves into the response stream, so it is held for the stream's whole lifetime: long-lived SSE responses consume permits, making the semaphore a true bound on concurrent upstream connections rather than only the request/header phase. Exhaustion fails fast with 429.
- Zero-valued knobs are rejected at startup (`validate_resource_limits`) — they would otherwise be silent kill switches.

## Tests
`test_exhausted_upstream_concurrency_returns_429`, `test_oversized_content_length_rejected`, `test_idle_stall_terminates_stream`, `test_total_deadline_terminates_stream`, `test_chunked_body_over_cap_errors_stream` + `test_body_under_cap_streams_intact` (wire cap: over-limit errors mid-stream, under-limit streams intact), `test_resource_limits_reject_zero`.

## Residual (documented)
Stream deadlines are generous fixed constants (SSE pauses while a model thinks); pathological-but-legitimate streams longer than 15min will be cut. Constants are documented in-code; knob-ifying them is trivial if ever needed.
