# AUD-035 — One undecryptable invitation blocks the mailbox loop (C-12)

**Severity:** Medium (availability) · **Status:** Fixed (wave 7, commit betterbase `ca6f6d5`).

## Root cause
`checkInvitationsInner` decrypted each payload outside any per-item error boundary: a single undecryptable (or structurally malformed) item rejected the whole pass, leaving later invitations and revocation notices unprocessed while the poison item sat at the queue head.

## Fix
Per-item isolation: each mailbox item is processed by `processInvitation`; failures are skipped, logged, and quarantined in a session-scoped in-memory set (`undecryptableInvitationIds`) so subsequent polls do not re-attempt decryption. The quarantine is pruned of ids the server no longer returns (expiry/deletion) so it cannot outgrow the mailbox. Items are never deleted on decrypt failure — a wrong-key situation may be transient and the server's 7-day expiry bounds retention. The pre-existing delete-on-invalid-JSON behavior is unchanged (now inside the extracted method).

**Review note (deliberate tradeoff):** a revocation notice whose processing *throws* (as opposed to returning false) is also quarantined until restart. This is acceptable because revocation is independently enforced server-side — the next sync operation fails with 403 and triggers `handleRevocation` through the transport — so the quarantine only delays notice cleanup, never enforcement.

## Tests
`continues past an undecryptable invitation (AUD-035)` (space-manager tests): poison item first, valid second → loop returns count 1 and the second invitation's space record is created; second poll makes no new decrypt attempt for the quarantined id. Verified failing on the parent commit.
