# AUD-052 — Photo upload queue failures invisible; "Synced" shown while bytes pending

**Audit finding (E-08):** photos derived status solely from `useSync`/`useConnectionStatus`; the gallery's uploading indicator stopped when the local `onUpload` completed while the file queue could still be pending or failed (uploads are async to the queue). The SDK's `useFileUploadQueue` existed but no example used it.

**Fix** (`betterbase-examples` commit `a130637`, SDK doubles `dd00ad1`):
- Shared `UploadQueueStatus` badge in the header (via `LessAppShell`/`HeaderBar` pass-through): pending count while uploading; failed count with a retry control on error, failure taking precedence.
- `effectiveSyncStatus` (pure, unit-tested): downgrades connected-and-idle "Synced" to "Syncing" while uploads are in flight; offline/error pass through unchanged.
- Photos wires both to `useFileUploadQueue().retry`.

**Regressions** (`shared/src/layout/UploadQueueStatus.test.tsx`): empty queue renders nothing; pending count; failed count + retry invoked; failure precedence; and all four `effectiveSyncStatus` truth-table rows.

**Verification:** shared + photos checks green; platform e2e green. **Status:** Fixed (wave 6).
