# AUD-011: Password recovery/change does not revoke prior authenticated sessions

- Type: Defect (implementation limitation)
- State: Fixed 2026-09-21; verified locally incl. PostgreSQL-backed tests ([evidence](../evidence/2026-09-21-remediation-wave4.md))
- Severity / rationale: High — old auth JWTs (14-day) and app refresh tokens remain usable after credential rotation
- Confidence and evidence basis: source-confirmed, re-verified 2026-09-20
- Owner: remediation wave 4
- Affected repositories, revisions, and local patches: `betterbase-accounts` fix `2af68a8` (migration 0002, jwt.rs claims, extract_auth, password-change/recovery handlers, storage)
- Violated invariant / linked decision: INV-05; D-004

## Impact and preconditions

Someone retaining an old auth token could continue root/grant/key/account operations after the legitimate user changed or recovered the password; an old refresh token kept obtaining new access tokens.

## Remediation (implemented)

Accounts gain `credentials_version` (migration 0002). Auth JWTs embed the version they were minted under; `extract_auth` compares it against the account row and rejects pre-rotation tokens ("credentials changed, re-authenticate"). Password-change completion and recovery finalize call `revoke_account_sessions`, which atomically bumps the version and deletes every refresh family across the account's grants; the completion response mints its token under the new version. Login mints under the current version; fresh registrations under 0. **Accepted bound (explicit product decision documented at the check site):** OAuth access tokens for resource servers (sync/inference) are validated via JWKS only and are deliberately not fenced — their 15-minute lifetime bounds the exposure; refresh families are revoked at rotation time so no new access tokens can be obtained.

## Verification

Storage tests: `revoke_account_sessions` bumps the version, deletes all families across grants, climbs on repetition. Route tests (real OPAQUE registration upload through recover/finalize): pre-recovery auth JWT → 401 on /v1/auth/validate; completion token → 200; pre-recovery refresh family → invalid_grant. Verifier: remediation agent, 2026-09-21.
