# AUD-009: Root rotation lacks generation/completeness checks against concurrent changes

- Type: Defect (race)
- State: Fixed 2026-09-21; verified locally incl. PostgreSQL-backed tests ([evidence](../evidence/2026-09-21-remediation-wave4.md))
- Severity / rationale: High — concurrent consent/password-change interleavings strand grants under the old root or pair stale wrappers with a new root
- Confidence and evidence basis: source-confirmed race (legal schedule documented in review 01 A-07)
- Owner: remediation wave 4
- Affected repositories, revisions, and local patches: `betterbase-accounts` fix `a6be3f2` (migration 0003, rotate_root_key, handlers, protocol, web api client)
- Violated invariant / linked decision: INV-05; D-004

## Impact and preconditions

The rotation API accepted any grant list (including incomplete ones) and had no previous-generation check; storage overwrote the root and only the listed grants.

## Remediation (implemented)

Accounts gain `root_key_version` (migration 0003). `rotate_root_key` locks the account's grant set `FOR UPDATE`, requires the submitted list to cover it exactly, and compare-and-swaps the root on the expected version (bumping it). A stale snapshot or an incomplete list rejects 409 with nothing changed. Recovery semantics defined: a rotation with a new blob replaces it; without one the old blob is deleted (it decrypts to the retired root and would present a false recovery path). GET /v1/accounts/root-key returns the version; the request requires `expected_root_version` (no in-repo UI callers existed, so the protocol change breaks no flow).

## Verification

Route tests: success path bumps version + rewraps + replaces blob; stale-version retry → 409 "root key changed" with state unchanged; a grant added after the client's snapshot → 409 "must cover every grant" with root untouched; rotation without a recovery blob deletes the stale one. Verifier: remediation agent, 2026-09-21.

## Residual (documented)

Same family as the AUD-008 residual: a consent committing after rotation with a pre-rotation root in memory strands its new grant; Closed in wave 5 (accounts `44be272`) together with the AUD-008 residual: the consent write carries the root version and the server CAS-checks it.
