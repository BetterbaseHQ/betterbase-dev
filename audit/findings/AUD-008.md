# AUD-008: Transient grant-read failures during consent silently generate replacement key material

- Type: Defect
- State: Fixed 2026-09-21; verified locally incl. PostgreSQL-backed tests ([evidence](../evidence/2026-09-21-remediation-wave4.md))
- Severity / rationale: High — loss of recoverability for newly encrypted records, loss of signing identity and shared-space access
- Confidence and evidence basis: source-confirmed
- Owner: remediation wave 4
- Affected repositories, revisions, and local patches: `betterbase-accounts` fix `5c395e9` (web consent page + new lib/consent-keys.ts; consent write path in oauth.rs; storage install_consent_key_bundle)
- Violated invariant / linked decision: INV-05; D-004

## Impact and preconditions

Consent treated every initial grant-read failure as "no existing grant" and generated fresh key material; the server preserved the old scoped wrapper while unconditionally overwriting the app keypair. One transient failure could permanently split the (scoped key, signing key) bundle.

## Remediation (implemented)

Client: scoped-key and app-keypair resolution moved into fail-closed helpers — failed reads, undecryptable wrappers, and malformed stored keypairs throw with retry guidance; only an explicit absence generates. The consent submit always pairs the app keypair with the wrapped scoped key it was encrypted under. Server: `install_consent_key_bundle` installs (wrapper, keypair) atomically — on an existing grant the keypair is written only when the submitted wrapper matches the stored one byte-for-byte; a stale-read submission is rejected 409 `invalid_grant_state` with stored state unchanged. A keypair without a wrapper is rejected (key material must land atomically).

## Verification

Route tests: bundle installs atomically on an empty grant; stale-wrapper submission → 409 with stored wrapper+keypair intact; consistent resubmission replaces the keypair; keypair-without-wrapper → 400. Web unit tests: full fail-closed matrix (read failure, undecryptable, malformed, absence-generates) for both helpers, byte-identical resubmission when reusing. Verifier: remediation agent, 2026-09-21.

## Residual (documented)

A consent created after a root rotation by a client holding the pre-rotation root in memory can still strand that new grant; closing that interleaving needs the consent write to carry the root version the client derived under (client + protocol change). Recorded for a later wave.
