# AUD-048 — Failed photo byte persistence leaves an undeletable unavailable tile

**Audit finding (E-04):** the record persisted before `File.arrayBuffer()` and the full blob's `FileStore.put`; a failure between left a live record pointing at absent bytes — an "Unavailable" tile rendered **before** the delete controls, so it could not be deleted from All Photos, and re-upload generated a new id rather than completing the record.

**Fix** (`betterbase-examples` commit `221d7d5`):
- Compensating delete: byte-persistence failure after record creation deletes the just-created record (milliseconds old; the synced-path tombstone converges ahead of any peer read) and evicts the partial cache entry, then still reports the failure with the filename.
- The Unavailable tile renders an always-visible delete control (no image to hover over), so historical/corrupt records stay destructible too.
- Drive-by from the reviewer's adjacent note: `deletePhoto` now awaits its cache evictions inside the caught chain instead of fire-and-forget `forEach` (rejections were bypassing the catch).
- SDK testing doubles gained `setFileUnavailable` + `useFileUploadQueue`/`setUploadQueue` so examples can render these states.

**Regressions:** import failure after record creation deletes the record and evicts the stubbed file id (`photos/src/App.test.tsx`); an unavailable tile deletes through the confirm dialog (`PhotoCard.test.tsx`).

**Verification:** photos `pnpm check` green (6 tests incl. build); platform e2e green. **Review round** (`662dff8`): import compensation also evicts the thumbnail cache entry when the post-thumbnail record patch fails.

**Status:** Fixed (wave 6).
