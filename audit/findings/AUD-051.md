# AUD-051 — Chat send clears newer drafts; retry duplicates committed message (E-07)

**Severity:** Medium · **Status:** Fixed (wave 9, commit examples `1750bd5`).

## Finding
(a) Send completion ran `.then(() => setText(""))` — clearing whatever was in the input at *resolution*, destroying a replacement draft typed during the pending send. (b) The input stayed active and Enter re-fired `handleSend`, re-submitting the still-present draft. (c) `sendMessage` commits the message put then patches the conversation preview with no transaction; when the put succeeds and the preview patch fails, the app preserves the draft and a retry performs a fresh `db.put` with a newly auto-generated id — duplicating the already-committed message.

## Fix
`ChatView`: a `sending` guard blocks double-fire (in-handler check covers Enter; the send button disables while pending — the input stays enabled so replacement drafts can be typed); success clears the input **only when the draft is unchanged** (`current.trim() === trimmed`); a failed send records `{text, id}` and a retry of the same text reuses the submission id. `sendMessage` accepts the optional id and passes it into `db.put` — an explicit id upserts the same record (verified end-to-end: TypedAdapter passthrough → `OpfsDb.preallocateId` honors record ids → Rust put upserts), so retry cannot duplicate. Modified text gets a fresh id (a distinct submission).

## Tests
`AUD-051: a replacement draft typed during a pending send survives completion` (also asserts a second Enter and a Send click while pending do not double-fire), `AUD-051: retrying a failed send reuses the submission id (no duplicate commit)` — both red on parent.

## Accepted residual
A replacement draft edited back to *exactly* the submitted text is cleared on resolution (string-equality semantics; vanishingly rare, documented rather than fixed).
