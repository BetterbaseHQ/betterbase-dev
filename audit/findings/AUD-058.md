# AUD-058 — No backup/restore recipe; no release-pinning gate (F-04)

**Severity:** High (assurance gap) · **Status:** Fixed (wave 10; examples `4bb0bac` + dev repo `scripts/release.sh`, `scripts/backup.sh`, `release.toml`, justfile).

## Finding
Green CI did not identify a reproducible platform release: no backup/restore recipes existed in the orchestration repo, and the examples CI checked out sibling repos (betterbase, json-joy-rs) at floating branch HEADs — a passing run proved nothing about which SDK revision the apps were checked against.

## Fix
**Release pinning**
- `release.toml` pins all six component repos at exact commits; the betterbase-dev commit containing it *is* the release commit.
- `just release-pin` stamps current HEADs (refuses on dirty trees); `just check-release` verifies every component is clean and exactly at its pin — the release gate.
- Examples CI sibling checkouts pinned to the same revisions (`ref:` exact SHAs), with the contract documented in the workflow: pins track release.toml, bump together, and CI needs the pinned commits pushed.
- First pin stamped at the wave-10 close: betterbase `eecda45`, accounts `fb3c5f1`, sync `a657e6b`, inference `8190318`, examples `4bb0bac`, json-joy-rs `11e07a3`; `just check-release` passes.

**Backup/restore** (`scripts/backup.sh`, `just backup` / `just restore <dir>`)
- Scope: production compose project (dev/e2e are ephemeral by design).
- Backup: `pg_dump` custom format for accounts + sync DBs; tar archives of the `sync_files` blob volume and the Caddy cert store; artifact presence verified before declaring success.
- Restore: stops app services, restores DBs (`pg_restore --clean --if-exists`) and volumes, then restarts **only the services that were running before** (a cold restore leaves a stopped stack stopped; no assumption of complete runtime env — proven when the full-`up` variant correctly tripped the new SMTP fail-fast on an unconfigured stack).

## Verification
Backup → restore round-trip smoke-tested against a real DB-only prod stack (containers up, dumps taken, restore completed, previously-running services restarted); `just check-release` exercised pass/fail paths (dirty-tree refusal verified during development); compose project-name handling accounts for a `name:` override.

## Documented residual
Backup coverage is the prod compose project only; a future S3 file backend would need its own backup path. Release pins protect CI examples; the Rust repos' own CI remains branch-based (their releases are consumed via release.toml, not their CI).
