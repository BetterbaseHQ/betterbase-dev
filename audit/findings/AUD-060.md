- Type: Defect (test infrastructure)
- State: Fixed 2026-09-20; verified locally ([evidence](../evidence/2026-09-20-remediation-wave0.md)); CI run pending push
- Severity / rationale: High gap — the advertised real-PostgreSQL gate provided no assurance
- Confidence and evidence basis: Reproduced at baseline (80 sqlx compile errors on fresh container); fix verified by execution
- Owner: remediation wave 0
- Affected repositories, revisions, and local patches: `betterbase-accounts` fix `8f44b39` (base `b7cda8872ee0`) (justfile, CI workflow, storage crate)
- Violated invariant / linked decision: plan Stage 4 "database and platform integration tests run as enforced gates, with unexpected skips failing the gate"; strengthens AUD-015

## Impact and preconditions

Any fresh test container: `db-start` applies no migrations, so live compile-time `sqlx::query!` checking fails (~80 errors); forced `SQLX_OFFLINE` still executes zero storage tests. Every storage-behavior claim was untested.

## Evidence and reproduction

Baseline evidence: [2026-09-20-baseline-accounts.md](../evidence/2026-09-20-baseline-accounts.md). Reproduction: `just db-down; just test-db`.

## Remediation

Root cause: recipe never migrated; no storage tests existed to run. Fix: per-test-schema harness (`postgres::test_support::test_storage()`) runs `sqlx::migrate!()` at setup; `test-db` sets `SQLX_OFFLINE=true` (compile via committed `.sqlx`; queries run live) + `BB_TEST_REQUIRE_DB=1` (missing/unreachable DB fails instead of skipping); 23 storage tests added across accounts/registration/verification/recovery domains.

## Verification

`just test-db` exit 0 on fresh container, 49/49 (23 storage live); `just check` green without DB and skip-only without `DATABASE_URL`; enforcement panic confirmed. CI workflow execution pending push. Verifier: remediation agent, 2026-09-20.
