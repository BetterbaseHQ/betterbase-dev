# AUD-049: Task read/modify/write without CRDT base can overwrite an intervening sync update (removes peer-added todos)

- Type: Defect
- State: Fixed 2026-09-21; verified locally (tasks `pnpm check` green incl. new regression; SDK checks green)
- Owner: remediation wave 3
- Affected repositories: `betterbase-examples/tasks`, `betterbase` (atomic `getWithBase` plumbing)
- Violated invariant: INV-03

## Remediation (implemented)

- New **`Database.getWithBase(def, id)`** (SDK): returns the record and its
  CRDT base from a *single worker dispatch* — the worker is
  single-threaded, so no sync application can interleave between the two
  reads (unlike `get()` followed by `snapshotBase()`, where the base could
  belong to a newer version than the returned view). Exposed through the
  `TypedAdapter` (sync path) as well.
- `todos.ts` ops (`addTodo`/`toggleTodo`/`deleteTodo`) now read via
  `getWithBase` and patch with `{ base }`: the todos-array edit is diffed
  against the read's snapshot, so a sync update that lands between the
  read and the write merges with the array edit instead of being
  tombstoned by the stale full-array view. The per-list write mutex is
  unchanged.

## Verification (regression tests)

- `tasks/src/App.test.tsx` "sync update landing between read and write
  doesn't drop peer todos": wraps the db so a peer todo commits after the
  op's read resolves but before its patch runs; asserts the toggle applied
  AND the peer todo survived.
- `betterbase/js` `OpfsDb.test.ts`: `getWithBase` dispatch/decode contract
  (record+base in one call, null handling).

## Residuals / judgement calls

- The wrapper's serialization still serializes only ops through one
  `createTodoOps` instance (as before); base-anchoring closes the
  sync-interleaving hole the finding describes.
