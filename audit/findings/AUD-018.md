# AUD-018 — Generated 64-bit actor IDs exceed the codec's 57-bit range (B-02)

**Severity:** Medium · **Status:** Fixed (wave 11; betterbase `607b3a6`, json-joy-rs `410e199`).

## Finding
`generate_session_id` built sids from 8 UUID bytes OR `MIN_SESSION_ID` — full 64-bit range — while the structural codec's `vu57` integer encoding represents 57 bits; the 8-byte branch's final byte is `(num >> 49)`, silently discarding bits 57–63. The audit **reproduced** the exact corruption: sid `(1<<63)+65536` passed the lower-bound-only validation and round-tripped through `model_to_binary`/`model_from_binary` as `65536` — stealing another actor's identity in every binary containing that history. `model_load`'s fork masked the symptom locally (future writes fine) without repairing encoded history.

## Fix (producer-side + codec guard)
- **betterbase-db** (`crdt/betterbase-db/src/crdt/mod.rs`): new `MAX_SESSION_ID = 2^57 - 1`; generation masks `(val | MIN_SESSION_ID) & MAX_SESSION_ID`; `is_valid_session_id` now enforces both bounds; `create_model`, `create_model_with_schema`, and `model_load` **return errors** for out-of-range sids — including caller-supplied ones (JS `PutOptions.sessionId` reaches `model_load`/schema creation through the WASM boundary), so the corruption can no longer be encoded at all. Two pre-existing test blocks that quietly used below-minimum sids (1000/2000) were invalid inputs nothing ever rejected — they now use valid sids.
- **json-joy-rs** (`crdt_writer.rs`): `vu57` and `b1vu56` final branches now `debug_assert` when a value exceeds their representable range — the codec stops hiding producer mistakes in test builds without changing the mirrored upstream wire format or its API.

## Tests
- `is_valid_session_id_rejects_above_codec_maximum` (incl. the audit's exact value), `is_valid_session_id_accepts_codec_maximum`, `generated_session_ids_stay_within_codec_range` (×1000).
- `create_model_rejects_unrepresentable_session_id` — the audit repro value errors at creation instead of encoding.
- `audit_repro_value_no_longer_truncates_through_round_trip` — a `MAX_SESSION_ID` model round-trips with identity intact.

## Documented residual
**Upgrade path (review round)**: databases created before this fix persist a full-width sid in the meta store (~99% out of range, since the old generator used 8 full UUID bytes) — loading it unmasked would hard-error every put/patch after upgrade. `get_or_create_session_id_on` now masks the persisted sid with `MAX_SESSION_ID` at load, which reproduces *exactly* the identity the old codec already wrote into every model binary (it truncated on encode) — existing histories keep their actor with no migration. Pinned by `legacy_out_of_range_persisted_session_id_is_masked_on_load` (red on the pre-mask parent).

Binaries written before this fix contain truncated identities by construction and decode exactly as they did before — no migration attempted. `b1vu56`/`vu57` release builds still truncate silently rather than error (wire-format compatibility); the producer-side rejection and load-time mask are the enforcement points.
