# AUD-056 — Prod compose omits SMTP env, advertises docker-internal sync endpoint, no file backend (F-02)

**Severity:** Medium · **Status:** Fixed (wave 10; accounts `fb3c5f1` + dev-repo compose changes).

## Finding
Three production misconfigurations shipped as defaults: (a) no `SMTP_*` env reached the accounts container — with `SMTP_DEV_MODE` defaulting to false the service built an `SmtpMailer` with an empty host and every verification/recovery email failed at send time with no startup signal; (b) `SYNC_ENDPOINT` defaulted to `http://sync:5379/api/v1`, a Docker-network hostname unresolvable from any browser, advertised in federation discovery; (c) the sync service had no `FILE_STORAGE` config and no data volume — files silently disabled in prod while enabled in dev and e2e.

## Fix
- **SMTP wired + fail-fast**: `SMTP_DEV_MODE` (default false), `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM` passed through in compose; accounts' `AppConfig::validate()` now **refuses startup** in SMTP mode without a host (3 unit tests; error message tells the operator exactly what to set). This is not theoretical: during the restore smoke test `up -d` on a stack without `SMTP_HOST` failed to become healthy for exactly this reason.
- **`SYNC_ENDPOINT`** default changed to `http://localhost:5379/api/v1` — at least reachable and obviously-local for bare stacks; named deployments must set the public URL (`https://sync.<domain>/api/v1`), documented in compose comments, the `.env` template, and AGENTS.md.
- **Files on by default**: `FILE_STORAGE=${FILE_STORAGE:-fs}` + `sync_files` volume (parity with dev/e2e; `FILE_STORAGE=none` disables). Dev override redirects the mount to `dev_sync_files`, preserving the dev/prod volume isolation — empirically re-verified that `down -v` removes only volumes attached to running containers, so a declared-but-unused prod volume survives `just dev-down -v`.

## Verification
Compose config parse (prod + merged dev); accounts `just check` green (188 tests + web); the SMTP gate observed live during the backup/restore smoke test; dev stack untouched by the file-volume redirect (dev override pattern identical to the existing DB volumes).

## Documented residual
A bare `just prod` with a default `.env` now fails accounts startup until `SMTP_HOST` (or `SMTP_DEV_MODE=true`) is set — deliberate fail-fast replacing silent send-time failure; documented in AGENTS.md and the `.env` template.
