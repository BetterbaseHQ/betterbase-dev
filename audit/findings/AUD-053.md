# AUD-053 — Default notebook/board creation failures bypass error UI; guard blocks retry (E-09)

**Severity:** Low · **Status:** Fixed (wave 9, commit examples `1750bd5`).

## Finding
Notes' and board's auto-creation of the default notebook/board was fire-and-forget — `createNotebook("My Notebook")` / `createBoard("My Board")` are async, so storage failures were unhandled rejections invisible to the user, and the one-shot `autoCreated` guard then blocked any retry for the mount. (Tasks already caught; board's local auto-create caught but kept the guard latched.)

## Fix
All three sites (notes authed, board authed, board local) now `.catch` → `reportError` (shared error UI) and **release the guard on failure**, so a later mount/effect can retry. Rejection propagation verified through `createNotebook`/`createBoard`/`createBoardWithColumns` (all rethrow).

## Tests
Covered by existing app suites (behavior: no unhandled rejection, guard resets). The tasks-app pattern was already correct and unchanged.

## Documented residual
A *partial* auto-create failure (board record commits, a child column put fails) leaves a half-populated default; the guard releases but `length > 0` then prevents re-running the effect. Pre-existing failure shape, now at least user-visible; reconcile-on-partial-failure noted as an optional follow-up.
