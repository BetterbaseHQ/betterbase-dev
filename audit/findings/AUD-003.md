# AUD-003: Recovery verification is not bound to the account being recovered

- Type: Defect
- State: Fixed 2026-09-20; verified locally ([evidence](../evidence/2026-09-20-remediation-wave1.md)); platform e2e verified 121/121 (2026-09-20)
- Severity / rationale: Critical — account takeover via token-for-one-email + request-email-of-another
- Confidence and evidence basis: source-confirmed, cross-verified; runtime path covered by route tests post-fix
- Owner: remediation wave 1
- Affected repositories, revisions, and local patches: `betterbase-accounts` fix `6cd6f62` (handlers/recovery.rs)
- Violated invariant / linked decision: INV-04/05; D-004

## Impact and preconditions

An actor controlling a recovery verification token for their own email and knowing a victim's email could init recovery against the victim's account and replace credentials/wrapper. See review 01 A-01 for the full argument.

## Evidence and reproduction

[Review 01 A-01](../reviews/01-identity-keys.md); verification evidence in the identity wave files.

## Remediation (implemented)

`recover/init` now validates the request email, canonicalizes the **verified token email**, rejects any mismatch before consuming the JTI, and drives both the rate limit and the account lookup from the verified identity.

## Verification

Route tests: cross-email token → 400 with victim credentials untouched; rejected binding does not consume the JTI (honest retry progresses to OPAQUE decode); non-recovery purpose rejected. Verifier: remediation agent, 2026-09-20.
