# AUD-047 — Interrupted board share leaves children referencing a tombstoned parent

**Audit finding (E-03):** `shareBoard` moves children, moves the board (new id, old tombstoned), then patches every child's `boardId`. A failure in the last stretch left children permanently pointing at the tombstoned board — invisible in the new board's view, unrecoverable by retry (a tombstone cannot be moved; `bulkMoveToSpace` throws on missing ids, so even a fresh re-share fails). The code comment claiming retries converge was too broad.

**Fix** (`betterbase-examples` commit `06aa06a`): a durable localStorage marker (old board id, target space, column id map, child ids, `boardCreatedAt` fingerprint) written before the point of no return; the board move is split as create-record → persist-id → tombstone so the marker always knows the new id before the old record dies. A crash between create and persist is resolved by **adopting** the created copy — matched by its preserved `createdAt`, since the raw adapter exposes no space metadata. The completion engine (`board-move.ts`) moves listed-but-unmoved children, skips already-tombstoned ids, rewrites FKs query-driven across **all** records still referencing the old board (catching children that arrived from sync mid-share; matching in JS because query filters are a middleware capability), and clears itself when converged. A mount-time reconciler runs it for any marker; corrupt markers are dropped instead of bricking mount.

**Scope:** the marker is device-local by design — only the browser that was mid-move can be mid-move; peers converge from the reconciler's patches once this device syncs.

**Regressions** (`board/src/lib/board-move.test.ts`, real local db): FK-patch-incomplete (the finding), pre-board-move, between-create-and-persist (adoption, exactly one live board), mid-children, late-arriving child, idempotent re-run, corrupt marker, unresolvable-state null return, plus the createdAt-preservation invariant adoption depends on.

**Verification:** board `pnpm check` green (13 tests); platform e2e green. **Review round** (`662dff8`): strays outside the target space are now MOVED into it (a patch never leaves the record's own space, so personal-space strays — e.g. a card added from a second device mid-share — would never have reached the invitee); the old board is always tombstoned (ghost-board crash state covered); adoption matches createdAt+name and refuses ambiguity; completions serialized process-wide; corrupt/unresolvable marker handling hardened; a remap bug in the move branch was found and fixed.

**Status:** Fixed (wave 6).
