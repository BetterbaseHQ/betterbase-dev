- What was built:
  - **Server**: `epoch_keys` table (migration 013) storing per-member JWE-wrapped fresh-epoch-key shares; `EpochStorage::put/get/prune_epoch_key_shares`; `epochKeys.put` (Admin-gated) / `epochKeys.get` (Read-gated, caller's own share by `auth.did` only); `membership.revoke` accepts optional `member_did` → `SessionRegistry.kick_member` detaches the removed member's subscriptions for that space via a per-connection detach channel (connection stays open for their other spaces; re-subscribe rejected by authorization); `AuthContext.expires_at` caps the WS connection deadline at token expiry + 5s grace (AUD-031); epoch.complete prunes shares ≤ epoch−2.
  - **SDK**: `removeMember` and `rotateSpaceKey` generate FRESH random epoch keys, distribute wrapped shares (self + active members, excluding previously-revoked DIDs) BEFORE any rewrap, re-encrypt the membership log under the new key, and complete; adoption (`adoptServerEpoch`, `completeInterruptedRewrap`, `handleEpochMismatch`) resolves keys share-first; `SyncTransport.resolveEpochKey` lets in-flight decryption of future-epoch DEKs fetch the share on demand; `WSTransport` rebuilds shared-space transports when the key changes (snapshot + bytes compare).
- Observed behavior: sync 15 suites green incl. new tests (epoch-key share storage roundtrip/replace/prune; epochKeys admin gating; revocation detaches the removed member's subscription with no further space data reaching the socket; token-expiry close at ~exp+grace); SDK green incl. new tests (fresh-key rotation persists a non-derived key and distributes shares before rewrap; removeMember names member_did, shares exclude the removed member, rewrap fresh; resolveEpochKey maps definitive not_found → null and rethrows transient failures; derived completion triggers a fresh re-rotation). Platform e2e full cycle **121/121** — rotation (single/multiple/three-member), revocation (forward secrecy, re-invitation, multi-space), realtime, federation all pass.
- Debugging record (two real defects found via e2e and fixed): (1) cached shared-space transports kept their original base key and only bumped the epoch label — under fresh keys this encrypted new DEKs with a key derived from the stale base while labelling them at the new epoch (AES-KW integrity failures on the next rotation); fixed by rebuilding the transport on key change with an independent snapshot immune to in-place zeroing. (2) `rotateSpaceKey` never re-encrypted the membership log — the next rotation's contact collection decrypted nothing and distributed shares to nobody; fixed by re-appending entries under the new key (as `removeMember` already did), plus the same step in `completeInterruptedRewrap` (code review #3).
- Code review: independent reviewer — design sound (share scoping, ordering, detach-channel architecture, AUD-031 math all confirmed); one blocker fixed (derive-fallback on transient share-fetch failure could rewrite DEKs under a wrong key — now only a definitive `not_found` falls back to derivation, transient errors rethrow, and derived fallbacks are never cached); should-fixes fixed in-wave (fresh re-rotation after derived-completion of orphaned advances; membership-log re-encryption in completeInterruptedRewrap; registry cleanup on connection teardown; canonical space keys; share pruning; doc-comment contracts; AUD-031 deadline test; resolver-fallback tests). Accepted gaps recorded below.
